# Finite owner-approved goal continuation

This backend adds a bounded launch mechanism under the existing organization scheduler. It is disabled by default. A plan preview is read-only; approving the exact preview stores a disabled plan. A separate confirmed, revision-checked action enables it. There is no provider trial or real organization enablement in development tests.

Each goal has one immutable plan containing at most 32 explicit templates and an original deadline within the goal deadline. Templates preserve their title, scope, typed acceptance definitions, required checks, delivery mode, leadership and selected workspace bindings. They may depend on exact existing milestone revisions and on earlier templates in the same finite list. Earlier-template dependencies require acceptance of the exact launched objective scope and typed contract. The system cannot invent extra templates or extend its deadline.

The scheduler checks its existing dispatch and execution-slot gates before advancing. One launch transaction checks current policy, pinned leadership, goal revision and cumulative allowances, milestone dependencies, selected project bindings, and directory identities; then it creates the objective, permanently attaches its goal membership, and records its one-time launch receipt atomically. The normal request claim, budget reservation, recovery journal and dispatch marker still govern execution. A lost acknowledgement or restart finds the retained launch receipt and cannot create another objective for the same template. Capacity or validation failures roll back partial creation. Cancellation, disable/re-enable, recovery and failed work never reset the finite template count or shared goal spend.

Policy, goal revision or dependency changes conservatively stop future launches. This first slice does not reauthorize a stale immutable plan. Owner-facing preview, enable/disable, current waiting reasons and a separately reviewed reauthorization flow remain follow-on work. It must not be described as a completed end-to-end milestone workflow until that owner interface and genuine hosted integration proof are available.

Tests use synthetic ledger states and injected executors only. They cover restart/concurrent launch, lost acknowledgements, receipt-write rollback, creation rollback, stale preview, exact retry, cancellation, deadline, allowance exhaustion, dependency revisions, directory replacement, finite template ordering, typed criteria, and existing scheduler dispatch/capacity gates.
