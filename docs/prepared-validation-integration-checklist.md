# Prepared validation integration gates

This is an implementation checklist, not a statement of available functionality.
The merged prepared runtime is experimental. The new contract and ledger remain
unregistered until the complete integration passes independent and native review.

## Authority and compatibility

- [ ] Explicit served-owner preview/save binds organization, owner, policy,
  source revision, sidecar revision, root and dependency directory identities.
- [ ] Existing project four-field bindings and recipe digests are byte-identical.
- [ ] Existing objectives never acquire a profile retroactively; new objectives
  select and retain an immutable sidecar in their creation transaction.
- [ ] No profile grants tools, editing, network or credentials. Null-recipe
  projects retain their edit prohibition.
- [ ] Unsupported platforms and missing prepared runtime prerequisites fail closed.
- [ ] Prepared source publication and project_build remain visibly unsupported.

## Mandatory pair and durable execution

- [ ] One retained effective snapshot contains every reviewed applied edit and
  matches exact source selection, exception hashes and preimages.
- [ ] Both run units are reserved atomically before TypeScript dispatch; all
  prior legacy/prepared objective and goal charges remain counted.
- [ ] TypeScript precedes Vitest, independent of step ID sorting. Both bind the
  same source/profile/bundle/authority and their own exact run and definition IDs.
- [ ] Resource nonce, container name/labels/image and staging identity are durable
  before use. Unknown create/attach/cleanup never enables replay.
- [ ] Exact descriptor-pinned dependency identity is checked on open.
- [ ] Trusted host receipt validation requires complete coverage, isolation,
  source-write prohibition, container cleanup and staging cleanup.
- [ ] Source/policy/root/dependency changes before either step, after execution,
  during review and at acceptance invalidate the set.
- [ ] Latest generation is authoritative, including failed/incomplete generations;
  no lookup can fall back to an older passed set.
- [ ] Independent review binds both run hashes and exact safe source evidence.
  A typecheck pass cannot satisfy project_tests.

## Cross-feature visibility: no prepared record may disappear

- [ ] Budget and goal views/admission include every prepared reservation.
- [ ] Recovery sees reservations, dispatches, resources, results and cleanup;
  only exact successful finish reconciliation is possible without new execution.
- [ ] Root revocation sees live and uncertain prepared resources and denies work
  before allowing narrow identity-verified cleanup.
- [ ] History/archive settlement rejects unresolved prepared execution or cleanup.
- [ ] Outcome generation invalidates on new set, result, review and cleanup events.
- [ ] Accepted dependency receipts reopen and verify the whole current pair.
- [ ] Replacement/continuation retain selected authority and historical charges.
- [ ] Evidence lookup, request lineage, snapshots and UI expose incomplete states
  and failures without treating claim metadata as verified receipts.
- [ ] Credential capsules and host/provider environments remain excluded.

## Required end-to-end evidence

- [ ] Real claim → dispatch → both actual tools → durable finish → independent
  review → reopened final acceptance using an isolated temporary organization.
- [ ] Real compiler error and real UI failure after compiler success block acceptance.
- [ ] Live revocation, stale source/bundle, later failed generation, forged receipt,
  self-review, missing step and uncertain cleanup fail closed.
- [ ] Crash at every persistence boundary retains charges and cleanup identity.
- [ ] Complete cross-feature union independently reviewed, then all applicable
  hosted native and regression gates pass on the exact merge tree.
- [ ] Actual postmerge workflows verified; no real user activation performed.
