# Typed outcome requirements

An objective can keep ordinary text criteria or explicitly declare how each requirement is proved:

- **Reviewed deliverable:** the final integrated artifact and its current review.
- **Verified check:** retained managed validation or project-test evidence. A model saying a check passed does not satisfy it.
- **Verified source integration:** current source integration evidence or an exact, verified owner handoff.
- **My explicit review:** an owner decision about the current requirement revision and exact deliverable bytes.

In the objective form, enter the requirements under completion options, then choose the evidence kind for each row. After a row becomes typed, use its row editor; bulk text editing is disabled so rearranging lines cannot silently change requirement identity. Scope amendment keeps typed identities and uses the same row editor. A replacement objective preserves the source requirements rather than converting owner review to an ordinary deliverable criterion.

The acceptance view shows the evidence kind and criterion revision. Open the final deliverable before recording an owner judgment. A judgment requires a reason and an explicit confirmation checkbox. Approval and rejection are separate actions. The decision binds the current organization, contract fingerprint, criterion, and deliverable fingerprint. If a response is lost, retry the retained exact decision rather than constructing another one. Losing the eligible owner identity disables retries until the original identity is available again.

An owner approval does not complete the objective by itself: all other required checks and the independent acceptance pass still apply. Criteria never authorize new tools or change filesystem permissions. Typecheck and build are separate evidence kinds in the backend contract, but are not offered as working checks until the trusted compiler receipt integration is available. Compiler success is never counted as functional-test success.

Legacy runtimes and objectives remain readable without typed fields. Malformed or mismatched typed snapshots are rejected rather than rendered as accepted evidence. Existing legacy string criteria remain compatible. The UI uses the application's controls, theme variables, and six supported language dictionaries.
