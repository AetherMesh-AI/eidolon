# Dependency-aware selective repair

A rejected outcome can reuse an exact reviewed task artifact only when the runtime proves its captured inputs remain unchanged. Stable criterion mappings narrow the failure candidates, but do not establish independence. The runtime adds actual dependency artifacts and retained agent-history task references to the dependency graph. Missing declarations, ambiguous failures, changed scope or policy, mutable artifacts, stale reviews, tool inputs and unsupported execution paths fall back to the existing bounded whole-objective replan.

The initial adapter supports project-free, tool-free managed draft/analyze tasks in both single-manager and executive-package planning modes. Executive packages carry the exact original manager plan forward in an immutable reuse record, with separately hashed current membership and remapped package dependencies. Original planning requests and usage remain historical; no new planning call is invented. Current tasks point to the repaired package in the UI, while verification retains their original execution membership. Changing an original plan or repaired membership fails closed. Active repaired packages retain manager and executive obligations. Explicit transfers of repaired package leadership are currently unsupported and fail closed; ordinary whole-replan fallback remains available when independence cannot be established. Source edits and integration-wide checks are conservatively invalidated. Build and typecheck never become test passes.

Repair decisions and reuse records are immutable. Reused output retains its original artifact, review and runtime input hashes; it has no fabricated execution request. Replacement work receives new task IDs linked to the originals, carries prior attempt and revision accounting, and consumes the same objective allowance and deadline. Synthesis and final acceptance run again. Reused evidence is checked again before integration/acceptance and shown as “Reused reviewed output” with the original round retained.

Whole-replan fallback preserves the established bounded replan behavior and all objective cost/stage history. It does not claim that prior output is reusable.

Repeated repair can conservatively fall back when the new worker or reviewer consumed prior-round history whose dependency closure cannot yet be proven independent. Package ancestry supports multiple immutable generations, but ancestry alone never authorizes another selective reuse. All original history and objective allowances remain in force.
